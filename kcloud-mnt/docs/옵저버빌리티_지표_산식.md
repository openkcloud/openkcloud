# 옵저버빌리티 지표 산식 (KCloud Monitor v2 연동)

`/monitoring` 화면 지표가 어떤 원천 API·필드에서 어떻게 계산되는지 정리한다.
구현이 추가될 때마다 이 문서를 갱신한다.

## 연동 구조
```
프론트 /monitoring  →  MNT-OBS (/api/obs/...)  →  KCloud Monitor v2 (이노그리드, master3:8000/api/v2)
```
- MNT-OBS가 Monitor v2에 **로그인(admin)→JWT 캐시(5h)·401 재로그인** 후 호출하고, 포털 형태로 가공해 반환한다.
- 프론트는 MNT-OBS만 호출(크레덴셜·CORS 비노출, single-origin).
- 코드: `MNT-OBS/app/monitor_client.py`(인증), `MNT-OBS/app/routers/monitoring.py`(집계), `MNT-APP/src/lib/obs-api.ts`(훅), `MNT-APP/src/app/(portal)/monitoring/page.tsx`(표기).

## 벤더 ↔ 화면 열 매핑
| Monitor v2 `vendor` | 모델 | 화면 열 |
|---|---|---|
| `furiosa` | RNGD | Furiosa RNGD (NPU) |
| `rebellions` | RBLN-CA22 | Rebellions ATOM (NPU) |
| `nvidia` | NVIDIA L40S | NVIDIA L40S (GPU) |

## 스코프 (집계 대상)
- 기본 `cluster=mgmt` → **mgmt 및 그 자식 서비스클러스터**(`parent_cluster=mgmt`)의 모든 가속기.
- 현재: furiosa(RNGD 1) · furiosa-okc-nb(RNGD 1, 노트북 전용) · l40s(L40S 1) · rebellions(ATOM 1) = 4대. Monitor v2의 `mgmt.accelerator_count`와 일치.
- mgmt 물리 노드 8대는 가속기 없음(가속기는 OpenStack VM 기반 서비스클러스터에 존재).

## 1. 가속기 공통 지표 (구현됨)

**원천**: `GET /clusters/{c}/nodes/{n}/accelerators` (서비스클러스터별·노드별 fan-out으로 수집) → 벤더로 그룹 → 집계.
**MNT-OBS 엔드포인트**: `GET /api/obs/monitoring/accelerator-summary?cluster=mgmt`

| 지표 | 원천 필드(가속기 객체) | 집계 | 화면 표기 |
|---|---|---|---|
| 온도 ℃ | `temperature_celsius` | 그룹 **평균** | 소수1 |
| 전력 W | `power_watts` | 그룹 **평균(장치당)** | 소수1 |
| 사용률 % | `utilization_percent` | 그룹 **평균** | 정수 |
| 메모리 사용량 | `memory_used_bytes` | 그룹 **평균** | ÷1e9 → GB(소수1) |
| 메모리 총량 | `memory_total_bytes` | 그룹 **첫 장치(대표값)** | ÷1e9 → GB(소수1) |
| health | `healthy` (bool) | **정상 개수 카운트** | `정상수/전체수 정상` |
| 전력효율(파생) %/W | `utilization_percent ÷ power_watts` | 장치별 계산 후 그룹 **평균**(전력>0만) | 소수2 |
| TDP 대비 전력(파생) % | `power_limit_percent` (= `power_watts ÷ power_limit_watts × 100`) | 그룹 **평균** | 소수1 |

**규칙**
- **평균 vs 합계**: 온도·전력·사용률·효율·TDP%는 **장치당 평균**(합계 아님). 전력 총합은 상단 KPI "서버 총 전력"이 담당.
- **메모리 총량**은 동종 장치면 동일 → 대표값(첫 장치). 사용량은 평균.
- **RNGD 열**은 furiosa + furiosa-okc-nb **2대 평균**(ATOM·L40S는 각 1대).
- MNT-OBS 집계는 소수 2자리 반올림, 화면에서 자리수만 조정.
- 데이터가 없으면 프론트는 목업값으로 폴백.
- idle 상태면 사용률·효율은 0.0(온도·전력·메모리·TDP는 실값).

## 2. 상단 KPI · 호스트맵 · 히트맵 (연동 예정)

이노그리드 가이드 기준 원천 엔드포인트(제공 상태). 현재는 목업이며 추후 MNT-OBS 중개로 연동.

| 화면 요소 | 원천 API (`/api/v2` 생략) | 상태 |
|---|---|---|
| 전력 효율 %/W | `/monitoring/power/efficiency` | 제공 중 |
| 저장소 사용률 % | `/storage/ceph/capacity` | 개발 중(목업) |
| 쓰로틀링 횟수 | `/clusters/{c}/nodes/{n}/accelerators/{id}/metrics` (`throttle`) | 제공 중 |
| 가속기 사용률 % | `/clusters/{c}/resource` | 제공 중 |
| 서버 총 전력 kW | `/monitoring/power/summary` | 제공 중 |
| 정상 노드 n/n | `/monitoring/overview` | 제공 중 |
| 호스트 맵 | `/clusters/{c}/nodes` (`utilization_percent`) | 제공 중 |
| 활용률 히트맵 | `/monitoring/metrics/timeseries?metric=&period=24h&step=1h&by=hostname` | 제공 중(metric 13종 허용목록만, 그 외 400) |
| 전력 분해 | `/monitoring/power/breakdown?dimension={vendor\|cluster\|node\|accelerator}` | 제공 중 |

> 전력 3계층(서버=IPMI ⊃ CPU=Kepler + 가속기=벤더 + 기타)은 **합산하지 않고** 독립 3라인으로 표시.
