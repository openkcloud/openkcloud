## 0. 한 줄 요약
목업(Next.js)이던 openKcloud 통합관리 포털을 **MSA 백엔드(FastAPI)로 실체화**하는 중.
동시에 **ETRI 관리망 테스트배드**에 AI 노트북(Kubeflow)·포털 DB·OpenStack 연동을 실제로 올리고 있다.

## 1. 저장소 구조 (모노레포, 2026-10-01 개편)
```
openkcloud/                 (git: openkcloud/kcloud-mnt, 브랜치 develop)
├── MNT-APP/      프론트 (Next.js 16, 기존 목업 v2 정렬본). ★ 실행은 여기서 npm run dev
├── MNT-CORE/     포털 코어 FastAPI — IAM·메뉴·공통코드. PostgreSQL 유일 소유자
├── MNT-IAAS/     OpenStack 중개 FastAPI — 프로젝트 조회 실연동 완료
├── MNT-PAAS/     K8s/Magnum 중개 FastAPI — 스캐폴드만
├── MNT-OBS/      Prometheus/Loki 중개 FastAPI — 스캐폴드만
├── MNT-WORKFLOW/ Temporal 서버(작업 장부) 배포 구성 — 우리 코드 없이 공식 이미지만 사용
├── MNT-AINB/     AI 노트북(Kubeflow) 중개 FastAPI — 기존 cmp-backend 귀속, 서비스 클러스터 조작
├── charts/       helm 차트·인프라 구성 — openkcloud-portal(포털 전체), infra/keycloak(테스트배드 Keycloak + realm 설정 파일),

├── docs/         문서 (아래 목록)
└── README.md     모노레포 안내
```
- MNT-AINB(AI 노트북 백엔드 = 기존 cmp-backend)는 **`MNT-AINB/`로 귀속**(2026-10-13, 그랜드파워솔루션). 경로 `/api/ainb`, 계정은 MNT-CORE 로그인으로 확인, AI 워크스페이스 신청은 자원신청 `ai-workspace` + Temporal `AiWorkspaceProvision`. 상세 `MNT-AINB/README.md`, 적용 순서·확인 사항 `docs/AI노트북_포털통합_안내.md`.
- 모듈 네이밍 규칙: 대문자 `MNT-CORE`(문서) / 소문자 `mnt-core`(k8s·이미지).

## 2. 아키텍처 핵심 결정
- **API Gateway = Istio(Envoy)** 경로 라우팅(코드 모듈 아님, 설정으로 제공). 각 모듈이 `/api/<도메인>` 직접 서빙. (oauth2-proxy 는 쓰지 않기로 함 — 아래 인증 방식)
- **인증 = Keycloak(OIDC).** 서버는 테스트배드·개발 모두 배포 완료(2026-10-12). **포털 연동은 개발 환경에서 구현 완료(2026-10-13)**, 로그인 테마 제작·개발 반영(2026-10-14) — 테스트배드 적용 진행 중(9장 4번).
  - 방식: **Authorization Code + PKCE**(공개 클라이언트, 토큰은 브라우저 메모리) + **Keycloak 로그인 테마** `openkcloud`(옛 `/login` 모양, `charts/infra/keycloak-theme`, '로그인 상태 유지' 기본 체크). 비밀번호를 포털이 받는 방식(ROPC, oc-cmp 방식)은 쓰지 않는다.
  - **CORE·IAAS 의 모든 API 는 토큰 필수**(`/healthz` 제외). CORE 가 토큰 검증(서명·`iss`·`aud=mnt-core-client`·`exp`)·포털 사용자 확인·세션(`sid`) 판정을 하고(`MNT-CORE/app/auth.py`), IAAS 는 CORE `/api/core/auth/me` 에 맡긴다(5초 캐시, `MNT-IAAS/app/auth.py`). 역할(admin/user)·소속 프로젝트는 **포털 DB** 기준.
  - 권한: 사용자는 소속 프로젝트 자원만 조회, 가상서버 콘솔·전원·네트워크/볼륨 연결·분리만 소속 프로젝트 안에서 허용, 보안그룹은 조회만. 그 밖의 쓰기·라우터·사용자/조직 목록·멤버 관리는 관리자. 요청에 담던 `username`·`owner`·`requestedBy`·`processedBy`·`role` 은 서버가 무시(토큰 사용자 기준). 포털 DB 에 없는 Keycloak 사용자는 403 "포털에 등록되지 않은 계정입니다…".
  - MNT-OBS·MNT-PAAS 는 아직 토큰을 확인하지 않는다(프론트는 토큰을 미리 붙여 보냄).

  | 환경 | 주소(토큰 발급자) | 배포 | DB |
  |---|---|---|---|
  | 테스트배드 | 관리: `https://keycloak.kcloud.etri:25443` / 로그인: `https://portal.kcloud.etri:25443/auth/realms/openkcloud_realm`(연동 적용 후) | helm 릴리스 `openkcloud-keycloak`(`openkcloud-mnt`, `keycloak-0~2`), 차트 `charts/infra/keycloak`, 이미지 `harbor.io:7443/mnt/infra/quay.io/keycloak/openkcloud-theme`(공식 26.7.4 + 로그인 테마) | `openkcloud-db` 의 DB `keycloak` · 스키마 `keycloak` |
  | 개발 | `http://keycloak.dev.okestro:8080/realms/openkcloud_realm` | Mac Mini(`172.30.1.200`) docker compose(colima) 1개, `charts/infra/keycloak-dev` | Mac Mini PostgreSQL 의 DB `keycloak` · 스키마 `keycloak` |

  - realm `openkcloud_realm`(표시 이름 openKcloud): **개발은 설정 완료**, 테스트배드는 가져와 테스트배드 값으로 변경·사용자 등록(2026-10-14). 설정 원본 `charts/infra/keycloak/realm/openkcloud_realm.json`(적용법 `docs/포털_배포_가이드.md` 6장).
  - 클라이언트: **`mnt-app-client`**(브라우저용, 공개·PKCE S256) / **`mnt-core-client`**(CORE 서버용, 비밀형·서비스 계정 `manage-users`·`view-users`). API 토큰 `aud` 에 `mnt-core-client` 가 들어가도록 매퍼 설정 → 백엔드는 이 값으로 확인.
  - 사용자 프로필: 이름 전체를 `firstName` 에(필수), `email`·`lastName` 은 선택(포털 사용자 5명 모두 이메일 없음). 아이디 변경·회원가입·비밀번호 찾기 꺼짐, 한국어만.
  - 테스트배드 주소 설계: 로그인 내내 호스트 `portal.kcloud.etri` 유지 — 포털 VirtualService 가 `/auth/realms/openkcloud_realm/`·`/auth/resources/` 만 Keycloak 으로 보냄(차트 `gateway.keycloak.enabled`, 기본 꺼짐). `keycloak.kcloud.etri` 는 **관리자 전용**.
  - 진입 흐름: `/`·`/login` → `/auth/login`(세션 확인 지점, `MNT-APP/src/app/auth/login`) → 세션 있으면 `next` 또는 `/dashboard`, 없으면 Keycloak 로그인 화면(로그인 후 `/auth/login` 으로 돌아와 원래 화면으로). 관리자 전용 화면을 주소로 연 사용자는 "접근할수 없는 화면 입니다." 후 `/dashboard`.
  - 세션: 브라우저를 껐다 켜도 유지(Remember me), 시간은 Keycloak 설정(미사용 30분·최대 10시간). 토큰은 계속 갱신하되 **사용자 조작이 미사용 시간 넘게 없으면** 로그아웃(idle). 직접 로그아웃·미사용·다른 탭 로그아웃·다른 곳 로그인(동시 로그인 제한, 브라우저 단위)·관리자 강제 로그아웃·미등록 계정은 원인별 안내 + 로그인 버튼. 세션 종료는 CORE 가 기록(`iam_user_session`, 원인 `IAM_SESSION_END_REASON`)해 그 토큰을 즉시 거부하고, 보이는 탭은 5초마다 `/api/core/auth/session` 으로 확인(접근 로그에서 제외). 상세는 메모리 `keycloak-login-decisions`.
  - 개발 주소는 접속 PC hosts 에 `172.30.1.200 keycloak.dev.okestro` 등록 필요. `.dev` 로 하지 않은 이유: 브라우저가 무조건 HTTPS 로 바꿔(HSTS) HTTP 로는 열리지 않는다.
  - 점검용 계정 `kc-test`(개발 realm). 개발 Keycloak 은 각자 PC 의 CORE 로 백채널 통보를 보낼 수 없다(강제 로그아웃 반영은 테스트배드에서 확인).
- **DB는 MNT-CORE만 소유.** IAAS/PAAS/OBS는 stateless — 상위 시스템(OpenStack/K8s/Prometheus) **라이브 조회**, 자원 실시간 상태는 DB에 저장 안 함(드리프트 방지).
- 설정은 전부 **env 주입**(12-factor): 파드 전환 시 비밀=Secret, 주소=ConfigMap. 프론트는 same-origin `/api/*`(게이트웨이 라우팅)로 백엔드 주소를 모르게.
- **자원 프로비저닝 = Temporal 워크플로.** 서버는 MNT-WORKFLOW(별도 파드, 저장소는 포털 DB 안 `temporal`·`temporal_visibility` 스키마), 워크플로 코드·DB 기록은 MNT-CORE 워커, OpenStack 작업은 MNT-IAAS 워커. CORE·IAAS 는 이 흐름에서 서로 직접 부르지 않고 Temporal 을 거친다. 상세 `MNT-WORKFLOW/README.md`.
- 상세: `docs/` + 메모리. (Keycloak 포털 연동은 **개발 환경까지** — 테스트배드 적용 진행 중, 9장 4번)

## 4. DB (MNT-CORE 소유)
- **개발 DB**: Mac Mini Homebrew PostgreSQL 17.11 (`172.30.1.200:5432`, db `openkcloud_portal`, user `portal_user`). 비번은 `MNT-CORE/config.env`(gitignore).
- **운영 DB**: 관리 K8s에 CloudNativePG로 동일 PG 17.11 구축 완료 (ns `openkcloud-mnt`). `docs/포털DB_PostgreSQL_설치.md`.
- **Keycloak DB**: 포털 DB 와 별도 DB `keycloak`(스키마·계정 `keycloak`) — 테스트배드·개발 같은 구조. 준비 SQL `charts/infra/keycloak-dev/keycloak_db.sql`, 상세 `docs/포털DB_PostgreSQL_설치.md` 8장.
- 스키마: `MNT-CORE/db/ddl.sql` + `seed.sql`. 테이블 명명규칙 `<도메인>_<단수>` snake_case (iam_/mnu_/cmn_/tkt_/mkt_/aud_).
  - 현재: `iam_user·iam_role·iam_user_role·mnu_menu·mnu_role_menu·cmn_code_group·cmn_code`
  - 공통코드: TKT_STATUS(pending/provisioning/completed/rejected)·TKT_TYPE·IAM_USER_STATUS (attr1=배지톤)
  - 마이그레이션: `db/migration_v0.2_ticket.sql`(자원신청·조직·프로젝트), `db/migration_v0.3_auth.sql`(`iam_user.keycloak_sub`, `iam_user_session`, `IAM_SESSION_END_REASON`) — ddl·seed 다음에 순서대로 적용
  - ⚠️ 새 테이블을 만드는 SQL 을 슈퍼유저로 적용하면 소유자가 그 계정이 되어 CORE(`portal_user`)가 못 쓴다(500 permission denied) → SQL 에 `ALTER TABLE … OWNER TO portal_user` 를 넣는다(v0.3 반영됨).
- ⚠️ PG15+ public 스키마 권한: `ALTER DATABASE .. OWNER TO portal_user` + `GRANT ALL ON SCHEMA public` 선행 필요.

## 5. 로컬 실행
```bash
# 프론트 — 의존성이 바뀌면(keycloak-js 등) npm install 다시
cd MNT-APP && npm install && npm run dev   # http://localhost:3000  (dev는 webpack — package.json에 --webpack)

# 포털 코어 (DB·Keycloak 필요)
cd MNT-CORE && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # PyJWT 포함
cp config.env.example config.env     # DATABASE_URL·KEYCLOAK_CLIENT_SECRET 수정 (Mac Mini DB, 개발 Keycloak)
.venv/bin/uvicorn app.main:app --reload --port 8000
# 최초: psql 로 db/ddl.sql + db/seed.sql + db/migration_v0.2_ticket.sql + db/migration_v0.3_auth.sql 적용(portal_user 로)

# IaaS (OpenStack 연동) — 사용자 확인을 CORE 에 묻는다(CORE 먼저 기동)
cd MNT-IAAS && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp config.env.example config.env     # OS_AUTH_URL 등 (아래 6장), CORE_API_BASE=http://localhost:8000
.venv/bin/uvicorn app.main:app --reload --port 8001
```
```bash
# 자동 시험 — 공용 개발 DB·OpenStack 은 건드리지 않는다
cd MNT-CORE && .venv/bin/pip install -r requirements-dev.txt && ./tests/run_tests.sh   # Docker 로 일회용 PostgreSQL
cd MNT-IAAS && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest tests   # OpenStack 호출 차단
```
```bash
# Temporal 서버(로컬 개발 서버) — 프로비저닝 워크플로용
brew install temporal                # 최초 1회
cd MNT-WORKFLOW && ./run-local.sh    # gRPC localhost:7233, 웹 화면 http://localhost:8233
# CORE·IAAS 의 config.env 에 TEMPORAL_API_BASE=localhost:7233 → uvicorn 기동 시 각 워커도 함께 시작
```
- 프론트가 바라보는 백엔드 주소: `NEXT_PUBLIC_CORE_API`(기본 localhost:8000), `NEXT_PUBLIC_IAAS_API`(기본 localhost:8001). 빈 값이면 same-origin(게이트웨이).
- **로그인(개발)**: 개발 Keycloak `http://keycloak.dev.okestro:8080`(접속 PC hosts 에 `172.30.1.200 keycloak.dev.okestro`). 계정은 개발 realm 의 `admin`(관리자)·`gy.yang`(사용자) — 포털 DB 사용자와 같은 아이디, 비밀번호는 Keycloak 관리자에게. `kc-test` 는 포털 미등록 계정(403 안내 확인용).
  - 로그인은 `localhost:3000`·`3001` 에서만 된다 — Keycloak 에 등록된 돌아올 주소·출처가 이 둘뿐이고, PKCE 는 HTTPS 또는 localhost 에서만 동작한다. CORE·IAAS 의 허용 출처(`CORS_ORIGINS`)는 `localhost:3000`.
  - 프론트 Keycloak 주소 `NEXT_PUBLIC_KEYCLOAK_URL`: 미설정 = 개발 Keycloak, 빈 값 = 같은 출처 `/auth`(테스트배드 `build:gateway`).
- **CORE Keycloak 설정**(`MNT-CORE/config.env`): `KEYCLOAK_ISSUER=http://keycloak.dev.okestro:8080/realms/openkcloud_realm`, `KEYCLOAK_JWKS_URL=<ISSUER>/protocol/openid-connect/certs`, `KEYCLOAK_AUDIENCE=mnt-core-client`, `KEYCLOAK_CLIENT_ID=mnt-core-client`, `KEYCLOAK_CLIENT_SECRET`(Keycloak `mnt-core-client` → Credentials, git 금지), `SESSION_SINGLE_LOGIN=false`(여러 개발자가 `admin` 을 같이 쓰므로 로컬은 동시 로그인 허용). 빠지면 API 가 503 `AUTH_NOT_CONFIGURED`.
- Swagger(`/docs`)로 API 를 부를 때는 Authorize 에 Keycloak API 토큰(Bearer)을 넣는다.
- 개발 Keycloak 은 각자 PC 의 CORE 로 로그아웃 통보(백채널)를 못 보낸다 → 관리 화면에서 세션을 끊으면 화면은 다음 토큰 갱신(최대 약 5분) 때 "로그인이 만료되었습니다…"로 안다(테스트배드는 5초 안에 "관리자에 의해…").
- ⚠️ **좀비 프로세스 주의**: 포트 충돌·Turbopack 패닉 시 `pkill -9 -f "next"; pkill -9 -f "uvicorn app.main"` 후 재실행.

## 7. 주의/함정 (겪은 것)

- **CNPG 이름충돌**: `kubectl get cluster`는 CAPI와 충돌 → `kubectl get clusters.postgresql.cnpg.io`.
- **Next 16 dev**: 기본 Turbopack이 이 프로젝트서 패닉 → `next dev --webpack`로 고정(빌드도 webpack).
- **리네이밍 시**: 테이블명 치환이 URL경로·라우트까지 오염 주의(테이블명과 API경로는 별개).
- **Keycloak 설정**: Web origins 에는 출처만(`http://localhost:3000`, 경로·`/*` 붙이면 403 Invalid origin), Client ID·realm 이름은 앱·발급자 주소와 묶여 있으니 바꾸지 말고 표시 이름(Name·Display name)만 바꾼다. 상세 `docs/포털_배포_가이드.md` 6.5.
- **IAAS 라우터 함수는 프로비저닝 워커가 직접 부른다**(`workflows/activities.py`) → 권한 검사는 데코레이터 의존성에만 두고, 워커가 부르는 함수의 인자는 바꾸지 않는다.
